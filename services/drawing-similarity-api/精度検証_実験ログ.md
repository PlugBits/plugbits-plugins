## 確定した知見

1. **OCR形状カテゴリは判別力ゼロ**（全候補が同カテゴリ一致で定数+0.08の下駄になっていた）→ SCORE_SHAPE_CATEGORY_BONUS=0 で無効化を仮採用
2. **支配的な失敗モード＝「同種部品の見た目似・別物」**。×候補の大半がクエリとAI形状タグを共有（フランジ同士・円筒部品同士等）。タグの語彙は部品種レベルで、同種内の別物を区別できない
3. **shapeTagペナルティの発動精度は低い**: dev25で発動15件中 ○6/×9（4割が誤爆）。0.1のまま維持、強化はしない（termDiagnostics で判断）
4. **メタデータ（材質・品名等）は現データではほぼ無効**: 一致がほぼ発生しない or 一致しても別物（productName match の×が複数）
5. **順位は実質ベクトル単独**で決まっており、クエリ内で○×を分離できないケースが多い（×のvectorRawが○より高い例が頻出）
6. **取りこぼしの実例**: query 3533 の類似 811（判定者認定）が検索上位10件圏外（vector類似 <0.911）。埋め込みレベルのミス。ランダム25本中1件の検出
7. **「類似が存在しない」クエリ**も実在（例: 2169。top vectorRaw 0.95・全滅）。有用率の分母には含める（実運用の正直な数字とするため）

## 追記(2026-07-27 対話による再解釈)

- **企業プロファイル確定**: 一点一様メインだが顧客図面はサイズ違いの類似品(小規模ファミリー、5,000件中に数個/ファミリー)が中心。全社の図面資産は70,000枚超(今回の検証対象はうち5,000枚)。この属性は製品のドンピシャターゲット(変形設計の製造業・多品種を扱う商社)に一致 → **この企業の数字をLPの数字にする方針で確定。2社目は不要**
- **蓋の件(3533→811)の再解釈**: 両者は別ファミミリー同士(811にも3533にも各自のファミリーが存在)。query 3533のシステム候補は5件全勝でファミリーを正しく上位表示しており、811は「別ファミリーだが参考になる」ボーナス級参照が11位以下だっただけ。埋め込みの重大欠陥ではない
- **P@5=57%の再解釈**: ファミリーが数個規模なら、完璧な検索でもP@5は構造的に40〜60%が上限。P@5はLP・改善指標から外し参考値とする
- **ゼロ○クエリの解釈**: 367/4863/2169は希少品タイプで「5,000枚中に正解なし」が自然。全量70,000枚なら存在する可能性はある(本番導入・アーカイブ取込の商談材料)
- **次の測定=ファミリー起点Hit率**: 判定者の記憶にある実在ファミリー10〜20組を eval/pairs.json に記載し、既存 eval/eval.js で Hit@k を測定。「類似品が存在する図面の◯%で上位5件以内に発見」をLP主数字の候補とする。全体有用率80%は脚注側
- SIMILAR_MAX_LIMIT(返却上限の環境変数化)と eval.js の API_KEY 対応を実装(取りこぼしの沈み順位診断用)

## 追記(2026-07-27 外れ値2枚の原因診断)

逆方向プローブと目視により、ファミリー測定の負け2クエリはともに「特定1枚の埋め込み外れ値」と確定。

- **4488(マイクロセパレータ)**: 344→3725はv0.9923で正常に近接。4488だけが家族全員から遠い。
  PDF1ページ目は鮮明な図面本体(表紙・品質問題なし)→ 容疑はauto_roiの切り出し or 埋め込みの癖
- **4433(座旋回角)**: 2071→1205はヒット。4433だけ孤立。目視の結果、**用紙は同じ向きのまま
  製品だけが90度回転して描かれている**。EMBED_ROTATIONSは画像全体の回転補正のため、
  「図中の製品のみ回転」は構造的にカバー外(製品を合わせると表題欄・文字が倒れて不一致)。
  **現方式の既知限界クラス**として記録
- 診断手法の確立: 全滅ペアは (1)recordId確認 → (2)逆方向プローブで外れ値特定 →
  (3)PDF1ページ目の目視、の順で数分で原因分類できる
