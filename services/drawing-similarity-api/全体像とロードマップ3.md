## 検証で確定した知見(要点のみ。詳細は実験ログ)

1. **fullモード採用**: 図面枠ベースのauto_roi切り抜きはスキャン起因のばらつきで信用できない(当初判断どおり)。A/Bで全面的にfull優位
2. **AIタグ・形状特徴は同種部品内の判別力なし**。順位は実質ベクトルで決まる。加工方法フィールドが次のprecision改善の本命
3. **既知の限界事例**: ①視覚的に似ていても埋め込みが遠い個体(4488) ②用紙同向きで製品のみ90度回転(4433、全体回転補正の構造的カバー外)
4. **正解リストは不完全側に誤る**(品名違いのファミリーを人間が見落とす)→ 測定値は下限。逆に「名前で探せない類似を形で発見」は製品価値の実例
5. **テナント名前空間**: 認証OFFでの登録はdefault名前空間に入り本番から見えない(事故1回)。登録系は認証ON+本番キーで

## システム構成の変更点

- 本番: `EMBED_IMAGE_MODE=full` + `QDRANT_COLLECTION=drawing_similarity_dinov2_base_full`(ペア厳守)。旧base(auto_roi)はロールバック用に残置
- 実験サービス `drawing-similarity-api-exp`: 本番同一env+SIMILAR_MAX_LIMIT=50。メモリ4Gi必須
- サーバenvの `KINTONE_BASE_URL/TOKEN` は誤テナントの遺物で削除予定(バックログ)

## ロードマップ

### 直近(進捗管理ボードのフェーズ1〜5)

```
_full再構築(サムネ+正テナント) → 本番切替 → プラグイン更新 → 2週間トライアル → 面談・LP
```

### インフラ・体制(トライアルと並行〜直後)

| テーマ | 内容 |
|---|---|
| **単独リポジトリ化+private化** | drawing-similarity(サーバ+プラグイン+検証資産)を plugbits-plugins から独立リポへ分離し非公開に。顧客データ由来の測定値・企業名を含むドキュメントを公開リポに置かない体制へ |
| **Qdrantアカウント移管** | 個人アカウント(yhtko)→ PlugBits へ。スナップショット移行で再埋め込みなしを狙う(ダメなら bulk-reindex で再構築)。移行後に QDRANT_URL/API_KEY を差し替え |
| mainマージ | 検証ブランチの取り込み(本番切替の動作確認後) |

### 機能・精度(トライアル後)

| テーマ | 内容 |
|---|---|
| 加工方法フィールド | 品目群単位の一括入力 → 再インデックス → SCORE_PROCESS_MATCH_BONUS の効果測定(実装済み・未検証) |
| 過去図面アーカイブ | 全社70,000枚超のうち残り約65,000枚の取込(商談材料。過去図面アーカイブ3段階設計.md) |
| 限界事例のR&D | 4488型(埋め込み外れ値)・4433型(図中回転)。ビュー単位埋め込み等の大掛かりな話なので優先度は商談次第 |
| test回(第三者判定) | LP脚注の説得力向上のため、先方現役担当者によるブラインド判定回 |
